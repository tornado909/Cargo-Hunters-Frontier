# Survivor Wear Guard — тестовый кандидат 0.1.0

**Не устанавливать в основную игру до нативной приёмки.**
Этот отдельный плагин создан под текущую штатную сборку Survivor **0.2.0**
(SHA-256 оригинала `aa77a6b3f3f4b5f4d3d24bbf841371de6d9ba72cf7e0681db80de7c7114ebb92`).

## Что делает

Плагин перехватывает приватный нативный метод
`DecreaseConditionItemOperation.DecreaseItemCondition`.
Восстановление прочности и операция покупки/ремонта им не изменяются.

Снижение прочности блокируется **только тогда**, когда одновременно:
- Survivor 0.2.0 сообщает, что забег активен и не завершён;
- операция выполняется в боевой сессии;
- штатная система предметов разрешает владельца ItemId в конкретного игрока;
- штатная SurvivorRun.IsHuman подтверждает настоящего игрока (не бота);
- предмет находится в активной экипировке того же игрока;
- уменьшение конечное и положительное.

При любой неопределённости или ошибке отражения возвращается исходное поведение
(fail-open); игровой процесс не должен зависнуть из-за невозможности проверить
владельца.

## Что реально проверено

- SDK net6, IL2CPP-ссылки Cargo Hunters 0.26.38.59, сборка на **ASC-AI**;
- `dotnet build -c Release -p:GameReferenceRoot=/private/path/BepInEx`: 0 ошибок/0 предупреждений;
- 145 управляемых проверок `ConditionPolicy` (все 16 комбинаций флагов с девятью значениями количества);
- релизная DLL находится вне игрового компьютера, исходник — в этом PR.

## Что НЕ проверено

- Успешность нативного перехвата при стрельбе или попаданиях в клиенте игры;
- отображение клиенту состояния прочности после подтверждения сервером;
- завершение забега и отсутствие влияния на обычные рейды;
- идентичный комплект и совместная сессия двух Steam-игроков.

## Сборка вне игрового ПК

```bash
dotnet build src/SurvivorWearGuard/SurvivorWearGuard.csproj -c Release \
  -p:GameReferenceRoot=/path/to/private/BepInEx
```

`GameReferenceRoot` — временный каталог с *совместимыми версиями*
`core/*.dll` и `interop/*.dll`. Не коммитить их в репозиторий.

## Нативная приёмка

1. Создать полную резервную копию тестовой Runtime; сохранить штатные DLL.
2. Установить WearGuard только в тестовую копию с текущим Survivor 0.2.0;
   не подменять Survivor предыдущей 0.1.3.
3. Проверить запуск меню без ошибок Harmony ABI.
4. Запустить одиночный Survivor, сделать ≥500 выстрелов, проверить,
   что клиент и сервер сохраняют прочность всех оснащённых предметов.
5. Проверить обычную карту — износ должен сохраниться.
6. Проверить смерть, выход из Survivor, повторный рейд и отсутствие утечек состояния.
7. Установить **один и тот же** комплект модов у хоста и гостя, проверить оба
   оружия, броню, отсутствие влияния на прочность ботов, один общий забег.
8. Сохранить журналы обеих машин, контрольные суммы и результат приёмки.

До прохождения тестов статус: **EXPERIMENTAL / NOT NATIVE VERIFIED**.
